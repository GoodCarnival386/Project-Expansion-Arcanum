# RSI 第三方集成 API 建议

适用环境为 Minecraft 1.20.1 / Forge。本提议涉及 RSI 原生递归合成、合成计划界面和取物流程。接口名称、注册方式和事件类型可沿用 RSI 现有风格。

## 1. 注册递归合成材料源

允许第三方注册材料源，让它参与规划、执行前校验、预留和实际取料。RSI 提供玩家、所选网络、已启用的材料来源、待查询的物品类型以及规划或任务上下文。RSI 按当前来源选择和取料顺序分配材料。同一个需求可以由多个来源共同满足，物品变体沿用 RSI 的匹配规则。

| 阶段 | 接口行为 |
| --- | --- |
| 规划 | 材料源提供可用于规划的可用量快照。试分配可以记录同一来源已经分配的物品与数量，回退候选方案时释放对应的临时分配。涉及玩家或实时库存的查询在服务端主线程读取，异步规划使用快照。 |
| 预留 | 为当前任务预留指定物品变体和数量，返回预留句柄或可识别的不足结果。预留只占用任务内的额度。 |
| 释放 | 放弃某项分配、取消任务或执行失败时，释放尚未提交的预留。 |
| 提交 | 重新校验来源可用性和预留，实际提取并返回交付的物品与数量。RSI 按真实来源和实际取得的数量记账。 |
| 返还 | 已经取得的物品随任务账本结算。任务失败或取消时，按 RSI 现有的实物返还流程处理。 |

同一来源提供的多种物品可能共享容量、次数或其他额度。例如，某来源总共可提供 10 个物品，预留 6 个 A 后就只剩 4 个名额可供 B 使用。来源需要获得同一任务内的累计分配信息，才能自行判断可用量。Refined Storage 和 Beyond Dimensions 使用同一套材料源契约。

## 2. 合成计划数据和界面扩展

提供只读的计划上下文，包含计划标识或修订号、合成次数、所选网络、已启用的材料来源，以及从任务外部获取的初始材料需求和可用的来源分配数据。初始材料应与前序步骤已经产出的材料区分。计划重算、切换配方、修改次数或变更来源时通知扩展，使扩展能把计算结果关联到对应的计划并丢弃过期响应。

计划界面允许扩展提供三类内容。

- **计划摘要行**，例如整份计划的成本或来源提示。
- **单项材料备注**，例如某个来源预计提供的数量。
- **单项材料 tooltip 附加行**，用于展示备注的完整内容。

RSI 负责测宽、留行、悬浮提示和布局刷新。扩展可以在计划标识不变时刷新自己的内容，例如库存变化后重新计算估算。

## 3. 递归合成成功通知

一条递归任务完成材料提交和产物结算后，在服务端主线程发出一次成功事件。事件包含玩家、任务 ID 和实际合成产物的只读快照。

- 记录普通配方、批量合成和机器步骤实际产出的物品。
- 记录最终产物和中间产物，包括随后被其他步骤消耗的中间产物。
- 将新合成的产物与退料、容器返还区分开。

## 4. JEI 取物和世界选块的失败回调

JEI 取物和世界选块可以共用一套后备处理器契约，各自在原生取物流程接入。RSI 先执行原生取物，确认本次操作交付数量为零后，在发送默认失败提示或触发收藏前，于服务端主线程调用后备处理器。已经交付部分物品的请求按原生结果结算。

处理器收到只读的原生结果和请求上下文，包括玩家、目标物品、请求数量、触发场景、交付目标，以及缺货、无网络、无权限或无空间等原因。RSI 执行原有的操作校验，各处理器负责校验自己的材料来源和交付条件。

| 处理器返回值 | RSI 的后续行为 |
| --- | --- |
| `PASS` | 本处理器经过无副作用的判断后放弃处理，RSI 继续询问下一个已注册处理器。所有处理器都放弃时，执行原有的失败提示或收藏流程。 |
| `DELIVERED(actualCount)` | 处理器已实际交付物品，数量必须大于零。RSI 以实际交付数量结束这次交互，停止调用后续处理器，跳过原有的失败提示和收藏。 |

客户端需要为同一次按键确定唯一的请求入口。如果 RSI 和另一个模组都识别 JEI 中键或世界选块，应有明确的输入优先级或协调接口，保证一次按键只发一次取物请求。
